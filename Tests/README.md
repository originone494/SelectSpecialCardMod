# 架构回归验证

从项目根目录运行 `powershell -File Tests/run-tests.ps1 -Headless`。
只运行控制台验证时省略 `-Headless`。构建不执行打包或部署。

当前控制台回归包含 65 项断言，其中时机效果的异步完成、异常和取消测试使用原版 ExecutionFinished 事件，验证独立时机流程能够收尾，并保留原异常/取消结果。仍须游戏内复测天之月只选一张后确认、镇魂棺手动召唤、镇魂棺/大圣棺装备目标，以及双叉/三极天龙的时机选牌显示。

控制台工程直接引用当前 Debug 构建，覆盖次数预占/取消/重入、Unicode 选择载荷、已知零值与未知效果、原子文件替换、异步来源隔离、展示缓存、真实 RitsuLib 局内保存和补丁共同加载。伤害探针仅替换最终落血阶段，实际框架包装及项目作用域补丁都参与验证；不代表完整游戏战斗测试。

GodotProbe 使用真实 Godot 主机，覆盖完整 Entry.Init 幂等性、关键功能补丁组、托管行动/右键/Sidecar 注册、连接素材计数、卡牌保存元数据以及 user:// 写入。它加载游戏程序集，不加载完整游戏资源或启动双端联机。

异响鸣灵摆检查执行实际手牌两端放置，验证两张声音卡获得原版 Retain 并锁定左右方向；新卡入手、静默插入顶部和排序操作都不能改变这两张卡的位置，发动条件要求手牌中没有任何已放置的卡；验证左右两张、仅左侧、仅右侧（包括发动者自己）均不能发动，两侧清空后才恢复条件。使用原版节点的最小手牌容器验证可见排列同步；通过原版 SavedProperties.Fill 验证放置资格、锁定方向与保留恢复。原版 CanPlay/ShouldPlay 判定、CardCmd.AutoPlay 和 CardPileCmd.Add 验证锁定卡无法手动或自动打出且留在手牌，混合入堆保持普通卡的结果顺序；存档恢复重建 Unplayable，离手后释放位置且只移除本次新增的保留与无法打出。默认蓝边；天使之声和恶魔之声被动效果适用时仍为蓝边。探针只模拟主动灵摆的发动资格，验证仅其满足条件时为金边，条件消失后回到蓝边。检查没有加载完整卡面场景或执行整个回合结束流程，实际动画与回合切换仍须游戏内复测。

特殊效果统一入口检查遍历当前 13 张特殊效果卡：等待演出完成才执行一次详细效果、演出中断不执行、演出期间原卡离开手牌不执行（39 项检查）。该项用可控任务替换资源演出，用计数器替换卡牌详细结算，验证实际统一入口与默认接口的异步顺序，不代表游戏内动画已验证。新增特殊效果卡会自动加入此检查。特殊效果的演出顺序为飞到中央、短暂停留、返回手牌并恢复原卡面，然后进入选牌/支付/结算；快速模式缩短时长，瞬间模式跳过演出。实际卡面飞行及震怒之日即时击晕提示仍需游戏内复测。

哀唱目标意图过滤、同战斗实体预占/成功记录、支付连锁后条件重查和五张驻场卡的真实画面仍须在完整游戏中验证；GodotProbe 没有加载战斗 UI、敌人招式状态或双端联机。特别要验证卡雷多哈特 Play 展示副本、杯满入手时的两帧布局等待，以及战斗中途恢复路径。

登场检查自动遍历当前 8 张登场卡，替换资源演出与详细效果，验证实际 DengChangHook 等待演出、同名每战一次、防重入以及中断/原卡离开手牌时跳过后续效果。使用真实 DrawWindowPatch 标记窗口，并只替换单卡入堆调用，验证抽牌不会播放登场演出。

装备生命周期检查使用真实 CardPileCmd.Add/RemoveFromCombat、原版 AfterCardPlayed/AfterCardChangedPiles 分发与 Ritsu 局内/战斗能力钩子展开，验证两件装备在直接弃牌、打出后弃牌、洗牌、回手与从抽牌堆自动打出后的弃牌中保留；回手预览仍包括合计 18 点加伤。消耗、除外、移出战斗、手牌直接回抽牌堆及打出后改为回手等非保留去向会卸下并各消耗一次。仅装备消耗命令的显示/卡牌连锁替换为实际入消耗堆的探针，不启动完整游戏战斗或装备消耗连锁。

除外关键字检查使用实际关键字列表、原版默认落堆方法、ModifyCardPlayResultLocation 与最终 CardPileCmd.Add，验证刻魔衍生物的手动/自动打出结果都为除外堆；模拟两次打出钩子后仍留在 Play，最终实际进入除外堆且不触发消耗。另给原版 StrikeIronclad 动态添加/移除关键字，验证通用性、普通弃牌/消耗去向及除外优先于消耗的默认规则，并检查关键字描述末尾的注册配置和本地化。装备检查增加真实除外 ResultPile 下的卸装与不重复消耗验证。上述检查控制可见监听器和战斗状态，不启动完整 OnPlayWrapper；衍生物的实际伤害动画、末尾「除外」显示及消耗装备的连锁仍需游戏内复测。

星爆气流斩检查验证 3 费/攻击/先古/消耗、卡池继承注册约定、卡图路径与描述绑定，使用原版战斗记录验证本人已完成攻击牌加伤、自动打出计数、技能/其他玩家/本次自身排除、后获得的卡读取既有记录及跨回合归零；实际动态预览与计算值一致。执行真实 OnPlay 构造攻击指令，仅替换 AttackCommand.Execute，检查一次指令包含 16 次命中、目标/来源正确且绑定同一 CalculatedDamageVar。未加载完整攻击场景，实际命中动画、伤害结算和消耗演出仍需游戏内复测。

GodotProbe 另复现了天之月、镇魂棺持久资产从已用堆直接调用原版 CardPileCmd.Add 时的 CombatState 校验异常，并验证公共恢复路径将两张原实体放回额外堆、发送牌堆通知且不注册到战斗卡集合。此项验证覆盖公共回堆机制；大圣棺融合的完整选牌、战斗副本退场和落泪之日入手仍需游戏内复测。

GodotProbe 使用实际 CardSelectCmd.FromSimpleGrid 和选择提供器复现唯一候选自动选中的分支，并验证必选的唯一候选、刚好够数的候选均交给选择提供器，以及可取消选择仍能返回空结果（4 项检查）。该项需要 Godot 的日志运行环境，在主机中执行；不替代游戏内鼠标/手柄的点击验证。

装备检查使用实际 KeMoEquipCapability、Ritsu 能力钩子展开和原版伤害预览，验证多件装备叠加、重复刷新不重复加伤、卸装后预览恢复及基础伤害不变；另验证静默移入装备堆后补齐手牌移除通知。主机未加载完整手牌场景，神圣棺原卡面移除、飞行特效和目标卡的实际文本仍需游戏内复测。

可装备光恶魔的主攻击伤害描述使用 {Damage:diff()}；装备检查读取实际 cards.json 验证魔轰神鲁力、魔镌客、震怒之日、刻魔衍生物、红泪之魔 落泪、赫赫君王及落泪之日的七项绑定，并验证落泪之日独立的消耗群伤文字仍为 12 点。

测试针对 .NET 9、Godot 4.5.1、游戏 API 0.111.0、RitsuLib 0.6.7 的 compat/0.111.0。`DOTNET_ROLL_FORWARD=Major` 只作用于测试期间，避免 Godot 默认选择当前 Harmony 不支持的 .NET 10。

换机器时检查工程引用路径及 `Local.Build.props`。业务日志中的 Sentry GDExtension 未加载提示是独立测试主机缺少游戏原生扩展的提示。

仍需在游戏内验证：双端私人配置不同的开局、断线/重连、存档继续与回放、召唤支付触发连锁、满手与取消、露莎卡/第二结界/爪音的完整多段伤害演出。测试不能替代这些场景。

本机项目目录执行 `.ps1` 时要求数字签名。最终验证采用下面的直接命令，未改变系统签名策略：

```powershell
dotnet build SelectSpecialCardMod.csproj --ignore-failed-sources
dotnet run --project Tests/Architecture.Tests/Architecture.Tests.csproj -- --patches
dotnet build Tests/GodotProbe/Probe.csproj --ignore-failed-sources
```

Godot 主机验证通过同一个 Probe 场景直接运行；测试文件写入自己的输出目录并在边界核对后清理。
